# 角色卡前端兼容设计（Card Frontend）

- 日期:2026-07-22
- 状态:草案,待作者评审
- 动机:linux.do 社区反馈——酒馆前端卡/美化卡导入梨园后美化归零。卡作者的界面既是沉浸感的一大块,也是创作表达;「机制更干净但颜值归零」不可接受。

## 1 背景

### 酒馆侧机制

ST 本体只提供两个底座:markdown 渲染 + 放行消息内原始 HTML。前端卡生态是社区凿出来的三层:

1. **提示词层**:强制模型每轮按固定格式输出状态数据(激进的卡直接输出整段 HTML);
2. **正则层**:卡自带 `regex_scripts` 在显示时把标记替换成预写的 HTML/CSS 模板;
3. **画布层**:替换结果渲染进聊天流;重卡靠「酒馆助手」(JS-Slash-Runner)跑内嵌 JS。

**酒馆助手是平台不是功能**:画布(消息内容渲染为沙箱 iframe)+ 脚本引擎(卡自带持久 JS,事件驱动)+ API 桥(变量/消息/世界书读写、触发生成、斜杠命令、音频)。MVU(MagVarUpdate)是跑在其上的数据管道框架:模型在正文输出 `_.set()` 指令→脚本解析进变量树→界面读变量渲染。

### 梨园现状

- `src/postprocess.ts` 策略引擎:状态类标签抽走画成梨园统一状态卡(`web/src/statusBlocks.ts`),送模历史整块删除(省 token 架构的一部分);
- `show_html` 工具 + `web/src/htmlEmbed.ts` + `HtmlFrame.tsx`:对话流沙箱 HTML 通道已存在,但是 agent 主动调用的调试级观感(工具条+徽章+560px 裁切);
- `panel_write` 侧栏面板:markdown/svg/html,agent 自建、随世界线回档;
- 卡导入:`normalizeCard` 运行时对象不带 `extensions`,但**卡文件原样保存在 `assets/cards/`**,`readCardRawJson` 可读回全量——`regex_scripts`/`tavern_helper` 数据未丢,兼容层不需要用户重新导卡。

## 2 三档分类

分界线不在「用没用某扩展」,在**界面有没有自己的行为**:

| 档 | 本质 | 数据来源 | 兼容策略 |
|---|---|---|---|
| 一档 静态美化 | 正则把标签换成 HTML/CSS 皮肤,纯文本变换 | 模型当轮输出 | **直渲**:显示层应用卡正则 |
| 二档 数据驱动展示 | 界面=状态的渲染函数(变量树→UI),无自主行为 | 变量树 | **agent 复现**:重建为账本驱动的梨园界面 |
| 三档 程序卡 | JS 即玩法:读+算+主动行动(改变量/发消息/自调 LLM) | 变量树+自身逻辑 | **沙箱照跑 + API 垫片**(复现=替人重写游戏,不可行) |

一张 MVU 状态屏卡若界面只读变量画图,功能上属二档;真三档是带按钮、玩法逻辑、反向操作宿主的卡。清理向正则(删思维链等)不属于任何档——梨园策略引擎已原生替代,直接忽略。

## 3 原则

1. **形式即内容**:宿主零痕迹,界面即舞台。把作者前端塞进带工具条的盒子=不可接受(2026-07-22 作者定调);
2. **不走回头路**:「模型输出变量指令+脚本抓取」的机制不回收;变量一律旁侧记账(scribe),主演正文零污染;
3. **正文红线**(D10 同款):垫片不提供改写/代写正文的通道;一切影响剧情的动作过 agent 总线裁决——酒馆助手让界面直接拧旋钮,梨园让界面递条子;
4. **复刻插座,不复刻发电厂**:只实现卡会调用的接口名(Wine 式兼容面),背后全接梨园已有器官;接口语义从公开文档学习,不读酒馆助手源码(D5 同款纪律);
5. **沙箱不退让**:形式隐形≠隔离取消,CSP 照旧、脚本帧永不给 allow-same-origin、无本机权限;
6. **裁剪不回升**:皮肤/界面只作用于显示层,送模历史清理策略一字不动。

## 4 呈现层(P0)

### 三种落位

1. **整楼界面**(消息本身是界面:界面卡每轮输出、HTML 开场白):不套消息气泡,界面即楼层本体——通栏宽度、高度跟随内容、无边框工具条徽章、背景透明贴聊天背景;
2. **正文内嵌块**(一二档皮肤产出的状态栏、正文中段组件):在正文流原位置无缝渲染,与上下叙事文字自然衔接,无宿主装饰;
3. **侧栏面板**(agent 自建/二档复现物):保持现有页签形态,不在还原范围内。

### 技术要点

- **宿主痕迹**:现有工具条(「交互界面/脚本/源码」)降级为悬停浮现的幽灵操作或收进楼层操作菜单;调试能力保留,视觉零常驻;
- **高度自适应**:脚本帧由注入的垫片 SDK 用 ResizeObserver 把内容高度 postMessage 给父页跟随;静态帧改 `sandbox="allow-same-origin"`(不给 allow-scripts,无代码执行,仅供父页测量)直接量高;取消 560px 上限;
- **样式主权**:`BASE_CSS` 退位为纯兜底(透明背景、图片不溢出),不再强制字体;卡样式原样呈现;
- **混排切分**:`splitHtmlParts` 升级——除 ```` ```html ````围栏与整段文档外,识别正文中的顶层 HTML 元素块(如皮肤正则产出的 `<div …>…</div>` 跨行段),切成 text/html 交替序列;
- **如实边界**(写进用户文档):依赖酒馆 DOM 类名或主题 CSS 变量的卡会降级;自包含前端卡不受影响。

## 5 数据供给层(P3 底座,二三档共用)

分工:**垫片管怎么应答,适配管答什么,scribe 管每轮更新。**

### 入梨适配(一次性,助手 agent 执行)

导卡或首次启用前端时,助手读四处数据:① `extensions.tavern_helper.variables` 初始变量树;② MVU 初始化块(世界书条目/开场白里的初始状态);③ 卡提示词中「每轮更新什么」的指令(不再发给主演,但它是 schema 说明书);④ 界面代码反向读取(它取了哪些变量路径)。

产出**卡前端清单(manifest)**:变量 schema + 初始值 + 各字段更新语义(「好感度 0-100,随剧情事件增减」)+ 与梨园账本字段的映射。形态:卡文件同目录 sidecar(`<卡文件名>.front.json`),明文可手改、跟卡分发。AI 只在生成清单时出场一次,无每轮翻译成本。

### 运行时

- **每轮供数**:清单并入 scribe 记账指令,旁侧模型每轮顺手维护 schema 内字段。变量账本与 rp-state 同构、进会话树快照、**随世界线回档**(回档后界面血条金币跟着回去,酒馆做不到);
- **垫片应答**:界面 `getVariables` → postMessage → 父页 → WS/REST → 变量账本取数返回;
- **修账兜底**:清单可手改;右栏助手「诊断/修账」职责自然延伸(「状态屏金币不动了」→读清单、对账本、修映射)。

### 二档复现的产物形态

推荐复现为「读账本的 html 界面」——与三档共用垫片读族与 scribe 供数,复现物零逐轮维护成本;简单场景也可用 markdown/svg 面板。故 P2 依赖 P3 底座。

## 6 垫片 API 三族策略

| 族 | 内容 | 策略 |
|---|---|---|
| 读族 | 变量读、楼层读、事件订阅、存在性/版本探测、高度上报 | **第一期实现**,账本/楼层视图供数 |
| 写族 | 界面改变量、代发消息 | 第一期不做;后续逐个裁决(「按钮替用户发言」可映射为用户输入,合法;「改写正文」永久拒绝) |
| 生成族 | 界面自调 LLM(generate/generateRaw)、STscript(triggerSlash) | 第一期不做,与正文红线冲突,降级提示 |

未支持调用:明确返回「梨园不支持此调用」+ 界面内可见降级提示,不静默失败。具体 API 签名在实现各族时**定点单页核对**公开文档(不做全量爬取)。

## 7 第一期范围与交付物

| 阶段 | 内容 | 主要落点 |
|---|---|---|
| P0 呈现层底座 | 三种落位渲染、幽灵操作、自适应高度、样式主权、混排切分 | `HtmlFrame.tsx`(模式参数化)、`htmlEmbed.ts`、`Messages.tsx`、`app.css` |
| P1 一档直渲 | 解析卡 `regex_scripts`(`/…/flags` 串、`$n` 捕获组、`{{user}}/{{char}}` 宏、trimStrings),筛显示向规则(`!disabled && placement 含 AI 输出 && (markdownOnly ∥ !promptOnly)`),显示管线应用;卡皮肤优先于统一状态卡;每卡开关(有皮肤默认开,卡详情可关) | 新 `src/cardfront.ts`(纯 TS 可测)、`server/rest.ts` 卡 payload 附规则、web 显示管线 |

## 8 第一期明确不做

写族/生成族 API;卡自带持久后台脚本(`tavern_helper.scripts` 常驻逻辑——卡逻辑永不以本机进程形态运行,MCP 亦不用于此,安全倒退);STscript/triggerSlash;音频 API;酒馆 DOM/主题环境仿真。

## 9 验收标准

- P0:HTML 开场白卡整楼无缝渲染——无工具条、高度贴合、样式原味;
- P1:仓库样本卡「淫宫美人录」状态栏按卡作者的 `<div>` 皮肤显示;另征集 2-3 张社区流行美化卡实测;关闭皮肤开关后回落梨园统一状态卡;
- P3:一张纯展示型 MVU 状态屏卡全链路跑通:适配生成清单→scribe 维护变量→界面渲染实时数据→回档后数据跟随;
- 全程:送模历史 token 占用不回升(对照现有裁剪测试);沙箱策略复查(脚本帧无 same-origin、CSP 不放宽)。

## 10 风险与对策

| 风险 | 对策 |
|---|---|
| ST 正则方言差异(flags/宏子集/独有语法) | `cardfront` 单测覆盖已知形态;解析失败的规则跳过并记日志,不炸整卡 |
| 垫片 API 名与真实文档偏差 | 实现时定点核对单页文档;探测式兼容(未知调用走统一降级) |
| manifest 读歪(适配是 AI 干的) | 明文可手改 + 助手修账工作流 |
| 恶意卡 HTML/JS | 沙箱+CSP 不退让;脚本帧永不给 same-origin;静态帧给 same-origin 但无脚本执行 |
| 界面依赖宿主 DOM/主题 | 如实边界,用户文档声明降级 |

## 12 术语

前端卡/美化卡=带界面美化的 ST 角色卡;酒馆助手=JS-Slash-Runner,ST 的卡端 JS 运行时平台;MVU=MagVarUpdate,变量管道框架;垫片(shim)=梨园实现的酒馆助手同名 API 兼容面;清单(manifest)=卡前端的变量 schema 与账本映射 sidecar 文件。
