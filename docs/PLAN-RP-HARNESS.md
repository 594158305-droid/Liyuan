# PLAN-RP-HARNESS：梨园 RP Harness 重建计划

> 2026-08-02 立项。前置事件：输入输出链路整体删除（director.ts / turn-intent.ts / compaction.ts /
> roleplay.ts 五个生成流程钩子，−1602 行），基线测试 334/334 绿。本文档是重建的设计契约。

## 0. 缘起与病根

过去一周的事故清单——steer 永动机、幽灵续轮、swipe 账本泄漏、脚手架重注自续燃、
thinking 排练（单轮 53k 字）、场记竞态、jiti 模块二象性——没有一条是"模型不会写"，
全部是**把 RP 跑在 coding agent 的循环上**的排异反应：

- 正文是"模型的回复"，输出不可逆 → 打磨只能发生在 thinking 里（排练）；
- 工具回执驱动续轮，续轮判定靠猜消息角色 → 幽灵轮、脚手架重注；
- 落树走 steer/followUp 队列语义 → 永动机；
- 账本是全局单线，会话是树 → swipe 泄漏；
- 质量机制全部实现为"循环里的补丁" → 每修一处，组合面多一层。

结论不是"去 agent 化"，而是：**agent 结构保留（LLM + harness + tools），harness 换职业**。
Claude Code 是指导模型写代码的 harness，梨园是指导模型演戏的 harness。

## 0.1 两个 KPI（2026-08-03 用户定案）

harness 的成败**同时**由两个指标判定，缺一不可：

1. **演得好**：剧情质量、人设一致、不失忆、不替用户做主。
2. **跑得快**：一拍的墙钟时间。慢是产品级缺陷,不是可以拿质量交换的代价。

第二条此前一直是隐含目标，正式写进契约。已确证的速度事实（8/02 实测，同一开局）：

| 思考档 | 思考量 | 一拍耗时 |
|---|---|---|
| off | 0 | **24s** |
| high | 22.6k token（在思考里预写全稿再誊出来） | **2m46s** |

**思考档不是旋钮，是二元开关**：zen go 对 reasoning_effort 无可靠节流（同题 low=187tok /
high=63 / 裸 enabled=364，无单调关系），实际只有 disabled 与放飞两态。故"调低档位求快"
不成立。思考档是用户自由，harness 不干预——但 harness 有责任让**开着思考也不至于慢到不可用**。

### 慢的三个来源（诊断，2026-08-03）

- **A 排练（占大头）**：模型在思考里预写整篇正文再誊进输出。8/02 三条 trace 九万字归类：
  生产 45% + 验算 25% + 纠结 5% = **75% 的思考是无效的**（有效仅读题 15% + 决定 10%）。
  治法是**拆迁而非抑制**：把每类无效思考对应的工作搬进 harness，通道无剩余职能，关不关都快。
- **B 预设无差别入场**：预设内容全量进上下文 = 全量占用模型注意力预算。实测 `双人成行`
  预设 **67 个启用块 / 49173 字**（分类学见 `_preset-taxonomy.md`）。但按性质该分层：
  文风类只需**在场**（模型照着写即可），禁词/句式/字数类**根本不该进写作阶段**（代码判得了，
  进去只会引发逐条验算）。R7 阶段供料已做块级分流（isPoliceBlock），**尚缺块内句级过滤**——
  文风块里夹带的"每段写完自检 X"仍在写作台上，是验算思考的残余燃料。
- **C 上下文膨胀**：长局全量历史 → 每拍 input 越来越大。M4 压缩正是治这一条。

### 提速三条路（优先级已排，M4 后执行）

1. **句级过滤验算指令**（收益大、风险低）：isPoliceBlock 从块级全留/全撤，细化到块内摘句——
   留"怎么写"，摘"写完自检"。直接砍 25% 验算思考。
2. **给排练断粮**：末端注入明示"思考只用于读题与决定，不在思考里起草正文"，draft_notes 作
   唯一可见规划区。便宜，但依赖指令遵循，需实测。
3. **预设分层产品化**（M5）：导入时按 `_preset-taxonomy.md` 自动分桶，让用户看见哪些块在
   写作阶段生效、哪些只在精修生效、哪些是纯噪声可关。根治，但要动预设页签 UI。


## 1. 概念对照（设计的北极星）

| Claude Code | 梨园 |
|---|---|

| 用户需求 | 用户角色的行动/台词 |
| Read / Grep | world_state_get / lorebook_search / memory_search |
| Write / Edit（精确替换） | 写初稿 / draft_edit 定点修订（一稿+补丁，永不推倒） |
| 编译器/测试/lint | checkDraft 程序化验收，违规带原文引用 |
| CLAUDE.md / 记忆 | 卡+预设（常驻）、世界书（触发）、剧情库（召回） |
| Plan mode / TODO | draft_notes 可见规划区（替代脑内排练） |
| git 历史 | 会话树（swipe=分支，天生的版本库） |
| 任务完成 = 测试过 | 谢幕 = 验收过，harness 判定，不靠模型宣言 |

## 2. 核心决策（R 系列）

**R1 台上循环自持**。台上（叙事）的 agent 循环不再是 pi 的 AgentSession，而是自建的
RpEngine：server 侧原生 ESM 普通模块，底下用 SessionManager 管树、`@liyuan/ai` 的
stream() 调模型。pi 只留给幕后（assistant 办事通道）。收益：harness **知道**当前是哪
一幕，不再从消息角色里猜——steer 队列、续轮判定、扩展钩子管线整类退场；引擎单实例，
jiti 二象性对台上路径死亡。

**R2 稿纸即工作区**。初稿阶段模型的流式输出**本身就是稿子**（不再经工具参数+JSON 桥）：
落树为普通 assistant 消息；修订以 rp-draft-op 补丁条目追加（old→new 精确替换），
树只追加不改写；显示与送模两侧用同一套补丁函数（src/draft.ts）得到当前定稿。

**R3 上下文 = f(分支)**。每次 LLM 调用的上下文从当前分支现算：
`[system(字节稳定)] [前情摘要] [往拍定稿] [末端动态区] [本幕指令]`。
往拍只留 user + 定稿正文，过程（检索/补丁/核验报告）**根本不进历史**——裁剪从减法
变成装配时就不存在。system 会话内字节稳定（缓存友好），动态内容全走末端。

**R4 世界 = f(分支)**。账本从当前分支的 rp-state 快照重建，磁盘文件降级为缓存。
swipe/rewind/世界线切换天然看到正确账本——泄漏整类消失，不再需要恢复桥。

**R5 验收三层**。
- 机械项（代码判）：字数/禁词/句式/模块/状态栏 —— checkDraft，已有；
- 不变量（代码判大头 + 窄题 LLM 兜底）：**用户主权红线**（稿子不得替用户角色行动/
  对白/内心决定）、账本一致性、语言失配。LLM 只判"是否替{user}做主？引用原句"这类
  有据可查的是非题，不判"好不好"；
- 品味（不判，归还用户）：swipe/世界线就是文字多值性的原生答案；editreply/重 roll
  是用户品味信号（远期回流进上下文）。默认**不设** LLM 质量门。

**R6 一拍即停，问=用户拉动**。RP 的用户每拍都在场，回合边界就是天然裁决点。harness
只执行两条结构规则：写完本拍即谢幕（停在把戏交出去的位置）；模型永不判断"该不该问"，
只有 harness 检测**用户文本**里的求方向信号才升格 ask（判定对象是用户的话，不是剧情）。

**R7 阶段供料（四阶段结构化）**。写作阶段只见文风/人称/字数/剧情要求；纪律块
（禁词表/禁八股/比喻原则/句式禁令，isPoliceBlock 判定）随核验报告在精修阶段送达。
draft_notes 可见规划区保留（开头几行写作要点）。

**R8 记账=场记独占（可回退）**。台上零世界写入工具；定稿后场记旁路调用提账本 patch。
主演通过正文里的状态栏模块表达状态变化，场记读取。若实测发现场记漏账/意图丢失，
回退方案是恢复"主演谢幕前一次收尾记账"（8/02 曾定案的形态）。

**R9 竞态两律**。回合互斥（下一拍装配等上一拍流水线收尾）；叶守卫（旁路结果落树前
核对分支位置，变了整体丢弃）。这两条明规则替代过去所有 ad-hoc 竞态补丁。

## 3. 一拍的解剖

```
用户行动
 ├─ 装配         上下文 = f(分支)（R3）；世界视图 = 账本 + 扫描命中世界书 + 记忆召回
 │               + 面板快照 + 登场名录；语言自愈检测
 ├─ 查资料(M3)   工具：lorebook_search / memory_search / world_state_get，封顶 3 次；
 │               模型输出正文即视为动笔（工具循环自然结束）
 ├─ 写初稿       流式输出 = 稿纸 v1，落树为 assistant 消息
 │               （开头 draft_notes 要点；正文含状态栏模块）
 ├─ 验收(代码)   checkDraft + 主权红线 → 违规清单；通过 → 谢幕
 ├─ 精修(≤K=2)   此时才给：纪律块全文 + 违规清单 + 当前稿
 │               → 模型出 draft_edit 补丁 → rp-draft-op 落树 → 复验
 ├─ 记账         场记旁路调用 → applyPatch → rp-state 快照落树（叶守卫）
 └─ 谢幕         harness 收轮。没有收笔宣言，没有可续的循环
```

树上每拍：`user / assistant(初稿) / rp-draft-op* / rp-state`；周期性 `rp-summary`。
旧会话完全兼容（全是既有条目类型，rp-summary 为新增）。

## 7. 预设分层产品化（M5 主项，2026-08-03 用户定调）

### 病根的实测量化

一拍送模上下文构成（双人成行预设 67 启用块，隔离舞台实测）：

| 段 | 字数 |
|---|---|
| system·卡+规则+工具（harness 自己的） | 1377 |
| system·预设块 | 6094 |
| 历史（2 拍） | 79 |
| 末端注入·harness 动态区 | 77 |
| 末端注入·预设 postHistory | 3442 |
| **合计** | **11069** |

**预设占 86%（9536 字），harness 自己只占 1454 字**。用户原话「预设直接污染了我们的
harness」精确化为：**内容被无差别塞进上下文，而上下文预算就是注意力预算**。

### 分桶：从「通道轴」加一条「性质轴」

现在预设页签的三个页签（采样参数 / 系统区 / 末端注入）是**递送通道**轴——内容送到哪。
用户要的第四个板块是**性质**轴——内容是什么。两条轴混在一个维度里是当前的结构问题。

性质四类（`src/preset-classify.ts` 实测分布，块数/字符）：

| 类 | 含义 | 去向 | TGbreak | 双人成行 | 夏瑾 |
|---|---|---|---|---|---|
| **文风** style | 怎么写：叙事/对白/视角/节奏/感官 | 写作阶段在场（= 用户说的「做完提示词就行」） | 27 块 7213 | 26 块 13838 | 8 块 3999 |
| **纪律** police | 禁词/句式/比喻——代码判得了 | **只在精修阶段**送（R7 已实现） | 3 块 1169 | 2 块 1526 | 1 块 130 |
| **结构** format | 输出模块/标签/顺序/字数 | 写作阶段在场 | 5 块 2146 | 4 块 2317 | 1 块 147 |
| **噪声** noise | 空赋值、纯分隔标题、注释块、破限话术 | **不入场** | 10 块 786 | 35 块 507 | 2 块 17 |
| | | **写作入场省下** | **17%** | **11%** | **3%** |

**⚠ 一个被自己抓到的错**：分类器初版把 `{{setvar::hook:: <真·写作指令> }}` 整条当成
「只有变量赋值，无可见内容」判为噪声——双人成行的「防打断」「Claude 详略得当」
「扩写+加强复述」都中招，**若直接上线等于静默删掉预设内容**。修正：setvar/addvar 的
**值是真内容**（后由 `{{getvar}}` 放出送模），只剥宏壳不剥值；只有空赋值才是噪声。
噪声量因此从虚高的 6384 字回落到 507 字。顺带补上 `isPoliceBlock` 的英文键名漏网
（`Forbidden_Expressions` / `Writing_Proscription`——双人成行的「Claude 禁词表」
此前一直漏进写作阶段）。

**结论修正**：噪声块的收益（省 3–17%）**小于分桶前的估计**。真正的大头仍是文风类
（双人成行 13838 字），而文风按定义就该在场——所以**分层的价值不在省字节，在于
让用户看见预算去哪了、并能自己决定砍哪块**。这与「品味不由 harness 判」是同一条原则。

### 待建

1. ✅ `src/preset-classify.ts`：`classifyBlock(content, name) → {kind, reason}`，
   纯函数已落地（8 条测试）。`isPoliceBlock` 作为 police 判据并入。
   **兜底归 style**——摘错文风比慢更糟。
2. ⏳ 预设页签：性质视图 + 每块显示分类与 reason + 用户可手动改判（按块指纹持久化）。
3. ⏳ 导入报告：「67 块 18188 字 → 写作阶段实际入场 16155 字」，让用户看见预算去哪。
4. ⏳ 装配接线：噪声块不入场。**最后做**，见下面的上线策略。

**上线策略（风险控制）**：分类器误判会改变演出效果。故 **先只报不砍**——页签与导入报告
显示分类，但默认仍全量入场；用户确认分桶合理后，再开「按性质入场」开关。
这条纪律来自本节那个 setvar 误判：**若当时直接接线，双人成行的三个核心写作块会被静默删掉**。

每个里程碑：测试钉住 + 单独提交（提交前经用户过目）。
**M0–M3 已完成但尚未提交**（用户要求提交前过目）。

## 6. 风险与备忘

- packages/ai dist 停在 7/18（tsgo 缺失无法重建）：引擎所需 stream()/completeSimple
  已在 dist 中可用；**流式开关通用化仍是运行时死代码，发版前必须重建 dist**（独立事项）。
- MCP 工具台上暂缺（幕后可用）：视觉识图等本属幕后任务；台上如需，M5 后议。
- 命令迁移清单以 roleplay.ts registerCommand 现存 17 条为准，迁移期两边并存不冲突
  （共享同一 SessionManager 实例）。
- 中断语义 v1 从简：流式中 abort → 本拍不完整但可见，下一条用户消息开新拍。
- 思考档位是用户自由（8/02 定论），引擎透传不干预；质量装置是可见规划+验收+补丁，
  不依赖关思考。但**开着思考也不该慢到不可用**——见 §0.1 提速三条路。
- **实弹探针必须新建空白会话**（8/03 教训）：旧会话历史里上一拍的正文会被 scanEntries 命中、
  或被模型直接复述，让"是否主动检索"这类验证完全失真。
- **末端注入不得压住用户提问**（8/03 教训）：注入块若排在本拍用户原话之后，模型会把提问
  当成历史旧话——既不检索也不正面回应。装配须保证**用户的话是上下文最后一句**。
- **未修：DSML 工具调用偶发泄漏成正文**（8/03 发现）。high 档实弹中出现一次：模型把工具
  调用写成 `<｜｜DSML｜｜tool_calls><｜｜DSML｜｜invoke name="lorebook_search">…` 的**文本**
  直接流进正文并落树（该拍正文只有 170 字，全是这段标记）。频率约 1/9 会话，
  与 M4/M4.5 改动无关（deepseek 侧 tool-call 序列化偶发退化为纯文本）。
  处置方向：`cleanAssistantText` 加一条 DSML 标记剥除 + 该拍视为工具调用重试；
  独立缺陷，不混进当前里程碑。

### 提速实测（2026-08-03，M4.5）

隔离舞台 + 真预设（双人成行 67 块）+ deepseek-v4-flash，同一开局三拍。

**low 档（首轮探索，样本不足）**：基线 15.3s→断粮 12.0s 看着 −22%，复测变成
13.7s→13.5s。差异落在噪声内。且 low 档每拍只思考几百字，本就没有可省的东西。

**high 档（正式对照，3 轮 × 3 拍 = 9 拍/组）**——这才是病例所在（思考量是 low 的十几倍）：

| 条件 | 平均一拍 | σ | 思考均量 | σ |
|---|---|---|---|---|
| 断粮关 | 26.6s | 3.7 | 10157 字 | 2839 |
| 断粮开 | **29.1s** | 8.1 | **14106 字** | 7513 |

**结论：指令式断粮被证伪**。不但没提速，均值方向还是反的（墙钟 +10%，思考 +39%）——
但这个"反"同样不可信：**组内 σ≈5.9s 远大于组间差 2.5s**，单拍实测跨度 12.8s–57.9s
（思考 362–14554 字），同一条件下相邻两轮能差三倍。真实信号是：**这个模型在 high 档的
思考量本身就是随机的**，与末端有没有那句话无关。

由此确认两件事：
1. **慢因 A 的治法不能靠说服模型**。"思考只用于读题与决定"这类指令，模型点头照做与否
   完全不受控（与 §0.1「思考档是二元开关，无节流」是同一现象的两面）。
2. **要治就得物理**：8/02 的 draft_write 工件化曾做到过（正文进工具参数，思考里预写
   无意义）。但它牵扯当年那批事故（steer 永动机、swipe 账本泄漏）的同一套机制，
   **须用户拍板才能请回来**。

方法论教训：**提速类改动必须跑 ≥3 轮对照并报 σ**。首轮 −22% 差点被当成成果——
样本量不足时，漂亮数字只是方差的一次抽样。

句级过滤（B）另议：对墙钟同样无可测收益，但全预设语料实测只命中 **4 行 / 3725 行**，
且全是真阳性（TGbreak「每一句对白之前先输出 html 注释做草稿自检」、双人成行「写完后
检查这段反应是否只在表演人设标签」）。收益小、风险已按「宁漏勿伤」压住（动笔前的一次性
读题/规划一律保留）。**留着不亏，但它是正确性清理，不是提速手段**。
