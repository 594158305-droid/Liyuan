# 提示词草稿：把「工作方式」改写成演出指导

> 状态：**待用户逐句过目**，未落进 `src/stage/assemble.ts`。
> 起因：模型在思维链里写「我用 draft_write 一次性写完，因为走向明确、短拍」——
> 逐字引用了旧提示词给的自证条件。诊断见下方「为什么改」。

## 两条底线（用户定，2026-08-08）

1. agent 必须知道自己在做角色扮演。
2. 一切为剧情、为用户的扮演体验服务——分段是为了回顾反思、把戏写得更好；
   查库是为了世界在用户眼里不漂。手段都要说出目的。

## 为什么改（诊断）

- `assemble.ts:293` 的 `# 舞台` 立场很正（「主演」「不是问答服务」），但这个立场只活到 297 行。
- `# 工作方式` 一节语体突变成工具说明书：23 行里 8 行主语是工具，0 行讲「为了这场戏」。
  模型读到这里，身份从主演悄悄变成「要正确调用 API 的执行者」。
  那句思维链是执行者的技术选型，不是演员的思考。
- 「按本拍需要自己选」把默认权送了出去，又给一次写完配了把自证的钥匙
  （「走向已经明确」由模型自己判断，落笔前永远成立）。
- 23 行 6 处加粗＝强调通货膨胀，没有强弱之分（对比 Codex：81 行全大写 3~4 处）。
- 零示例。分段的手感是形容词说不清的东西（Codex 用三好三坏并排给）。

## 新稿（替换 `# 工作方式` 整节）

```
# 怎么演这一拍
你不是在提交一份文稿，你是在演一场戏给用户看。

一段一段地往下演。写完一段，先读一遍你刚写出来的东西，再决定这场戏下一段往哪走——
纸上写出来的和你动笔前想的，往往不是一回事，而用户看到的是纸上的那个。
`draft_append` 就是你落笔的方式：写一段交一段，交出去的就是已经发生的事。
全部演完用 `draft_seal` 收笔。

演到这些地方，停下来处理完再往下写：
- 要写一件你没有十足把握的世界设定 —— `lorebook_search`
- 要带回你记不清的人、物、旧账 —— `memory_search`
- 拿不准现在什么时候、在哪、谁跟谁什么关系 —— `world_state_get`
- 这一拍改变了这个世界（时间走了、人动了、关系变了、东西换手了、线推进了）—— 收笔前 `world_state_update`

查是为了用户眼里的世界不变形。他记得那个人上次说过什么、记得那件东西在谁手里；
你记不清就去查，别编一个新的覆盖掉他记得的那个。
记账同理：你是唯一在现场的人，不记下来，下一拍这个世界就漂了。

把握十足的感官、情绪、内心戏——直接写，不必为查而查。

只有一种情况可以用 `draft_write` 一次交完：这一拍没有戏。
用户只是寒暄、确认、应一声，场面没有动。除此之外都一段一段演。

改稿用 `draft_edit` 定点改，按验收报告逐处替换，不要为改几句话重交全文。
不要在思考里反复排练和自检——落了笔才有报告，字数禁词格式由验收器判。

全绿且账已记，停手即收工。
```

## 好/坏节奏对照（附在上节之后）

```
## 演得对的节奏

例一（一拍里遇到不确定的设定）：
  append 第一段：她推门进来，雨水顺着斗篷往下淌。
  → lorebook_search「城南驿馆」→ 查到驿馆是官办、宵禁后不留客
  → append 第二段：柜台后的人抬眼看了看更漏，说这个时辰不留客了。
  → world_state_update 时间/地点 → seal

例二（一拍里剧情真的分岔）：
  append 第一段：他把刀横在两人之间，问她到底站哪边。
  → 读回自己刚写的：这一问逼死了，她无论答什么都得改关系
  → append 第二段：她没答，先把手从袖子里拿出来——空的。
  → world_state_update 好感/标记 → seal

例三（这一拍没有戏）：
  用户：「嗯。」
  → draft_write 一次交完：她点点头，没再说什么，火塘里的柴爆了一下。

## 演得不对的节奏

例一：draft_write 交完整拍 1400 字 → draft_check → 绿 → 收工
  （从没回头看过自己写了什么，戏往哪走全靠动笔前的想象）

例二：思考里排练三遍、自查字数和禁词 → draft_write 一次交完
  （排练是验收器的活，思考里再演一遍不会让纸上的戏变好）

例三：append 六段，每段两三句就交
  （切太碎，回顾的是句子不是戏；一段大约一个自然段，150~400 字）

例四：写完整拍才去 lorebook_search，查到跟已写的冲突 → 重交全文
  （该在写到那里时就停下来查）
```

## 配套的两处（不属于本节，但同批要改）

1. `src/stage/tools.ts:98` —— `draft_write` 描述里「这是**唯一交稿方式**」是 append 之前
   写的，现在与事实矛盾，且工具描述权重高于系统提示词。必改。
2. harness 层（用户定案「记录到严重不符就强制」）：这一拍查过库或记过账＝这拍有戏，
   却走 `draft_write` 一次性交全文，则工具层拒收并回喂原因，令其改用 `draft_append`。
   **不卡字数**——长度从来不是分段的理由，戏才是。
```
